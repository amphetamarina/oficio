## 1. Design Check Against README.md Concepts

The README currently frames ofício as:

- Obsidian as the table/workbench and single source of truth.
- Agents as invited hands, not a new center of command.
- Requests and responses as documents, not hidden application state.
- Minimal instruments, low modefulness, no dashboard, no separate inbox app.
- Visible, narratable logs in Markdown.
- Synchronization as an event of work.
- Changes should be auditable and reversible through plain text.

This plan follows those concepts as follows:

1. Completion/failure state stays inside the request’s Markdown checkbox.
2. Logs are Markdown files inside the vault, not a database.
3. Daily logs prevent one huge file while keeping search/navigation native to Obsidian.
4. Daily inboxes are optional and generated by date, but scanning can still include a stable main inbox for monotony.
5. Safe replace/patch tools operate only on explicit vault-relative files and should return diffs/previews where practical.
6. Hooks/cron should remain explicit and low-noise: default should be manual scan; optional scheduled scan can be documented/configured later.

## 2. Proposed Vault Layout

Keep the visible config under:

```text

```

Replace the single growing log file with dated notes:

```text
agent/oficio/log/daily/2026-04-25.md
agent/oficio/log/daily/2026-04-26.md
```

Recommended log note format:

```markdown
# ofício log · 2026-04-25

## test-001

- status: completed
- at: 2026-04-25T19:59:49-03:00
- source: agent/oficio/inbox.md

Read agent/oficio/inbox.md and appended confirmation.
```

Inbox options:

A. Keep one canonical inbox:

```text
agent/oficio/inbox.md
```

B. Add optional daily inboxes:

```text
agent/oficio/inbox/daily/2026-04-25.md
```

Recommended default: keep `agent/oficio/inbox.md` as the canonical scan target for monotony. Add daily inbox support as an optional path resolver, not as the default replacement yet.

Reason: a single place to ask work respects the README’s “uma única maneira” principle. Daily logs solve growth without fragmenting the act of asking.

Completion format in the inbox:

```markdown
- [x] @hermes id:test-001
  Original request text.
  - completed: 2026-04-25T19:59:49-03:00
  - note: appended confirmation to agent/oficio/log/daily/2026-04-25.md
```

Failure format in the inbox:

```markdown
- [!] @hermes id:test-001
  Original request text.
  - failed: 2026-04-25T20:10:00-03:00
  - error: note not found: agent/missing.md
```

Open question for implementation: Markdown task lists usually use `[ ]` and `[x]`; `[!]` is visually useful but not standard. If we want strict task-list semantics, use `[x]` plus `status: failed`. Recommended for Obsidian compatibility:

```markdown
- [x] @hermes id:test-001
  Original request text.
  - status: failed
  - failed: 2026-04-25T20:10:00-03:00
  - error: note not found: agent/missing.md
```

Use the recommended `[x]` + `status: failed` format unless the user explicitly wants `[!]`.

Replace behavior:

- `replace_once` must raise if `old` is empty.
- `replace_once` must raise if `old` does not occur.
- `replace_once` must raise if `old` occurs more than once unless a future `replace_all` option is added.
- This protects against broad accidental edits and matches the “desfazer universal” concept by keeping mutations precise.

Patch behavior:

- Do not implement a complex unified-diff engine yet unless necessary.
- Prefer `oficio_replace(path, old, new)` first.
- Add `oficio_patch` only as a thin multi-replace operation if needed later.

## 6. Hooks / Cron / Scanning Design

Current plugin has no hooks and no autonomous watcher. This is consistent with a manual, low-noise v0.

Options:

1. Manual scan only, current default.

   Best fit for the README’s “no interruption” and “agents are invited” principles.

2. Hermes cron job that asks the agent to scan periodically.

   Example outside the plugin:

   ```text
   Every 30 minutes: scan the ofício inbox, handle pending requests that are safe and fully specified, append results to the daily log, and mark requests complete or failed.
   ```

   This uses Hermes cron, not plugin hooks. It is visible in Hermes scheduler, easier to disable, and avoids hidden vault watchers.

3. Plugin hook `on_session_start` to inject pending count.

   Possible later. Example: when a Hermes session starts, scan inbox and add ephemeral context “ofício has 2 pending requests”. Do not auto-execute.

4. Filesystem watcher.

   Not recommended yet. It adds hidden state/process management and may fight Obsidian Sync timing. Consider only after the explicit protocol is stable.

Plan recommendation:

- Implement manual tools now.
- Document optional Hermes cron usage in README.
- Do not add a plugin hook or watcher in this pass.
- Later, add an opt-in `on_session_start` hook only if it stays informational.

def replace_once(text: str, old: str, new: str) -> str:
    if not old:
        raise ValueError("old text is required")
    count = text.count(old)
    if count == 0:
        raise ValueError("old text not found")
    if count > 1:
        raise ValueError("old text occurs multiple times")
    return text.replace(old, new, 1)
```

def append_request_log_entry(
    existing_log: str,
    request_id: str,
    status: str,
    source_path: str,
    message: str,
    *,
    timestamp: str | None = None,
) -> str:
    stamp = _timestamp(timestamp)
    entry = (
        f"\n## {request_id}\n\n"
        f"- status: {status}\n"
        f"- at: {stamp}\n"
        f"- source: {source_path}\n\n"
        f"{message.strip()}\n"
    )
    base = existing_log.rstrip() or "# ofício log"
    return base + "\n" + entry
```
